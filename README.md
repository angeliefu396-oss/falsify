A pack of rules that stops an AI from sounding certain when it isn't.

It installs as an **Agent Skill**, as an **always-on `AGENTS.md` block**, as a **single prompt file**, or as a **CLI** — the same kernel, four carriers. No knowledge base, no embeddings, no vendor lock-in.

---

## The problem

Models are optimised to sound right. Ask one for a serious answer and you usually get fluent prose, confident tone, and no way to tell which sentence came from a source, which from the user's own assertion, and which the model invented to fill a gap. The failure is not style. It is that **facts, evidence, inference, assumptions and unknowns arrive fused into one paragraph**.

You cannot fix that with "be rigorous". You fix it by making the separation mandatory, and by moving the parts that can be mechanically enforced out of the prompt and into code.

## Three layers

| Layer | What it is | Cost |
|---|---|---|
| **Kernel** (`kernel/core.md`) | 8-step loop + six hard rules + output contract + forecast discipline. Always in context. | ~1,800 chars |
| **Workflows** (`references/`) | 19 files: research, decision, execution, system building, forecasting, risk, audit, templates, regression tests. Read on demand, one at a time. | 0 until needed |
| **Enforcement** (`scripts/dcai.py`) | Probability ownership, append-only updates, sealed ledger, Brier scoring, small-sample guardrails. Cannot be talked out of. | 0 context |

The prompt carries judgement. The code carries arithmetic and integrity. Conflating them is why most "rigorous prompt" packs decay after a month.

## Quick start

```text
# 1. As an Agent Skill (Claude Code, DSH, any client implementing the Agent Skills layout)
git clone https://github.com/dcai-kernel/dcai-unified-kernel.git
cp -r dcai-unified-kernel ~/.claude/skills/dcai-unified-kernel     # or ~/.dsh/skills/

# 2. As an always-on kernel for any agent that reads AGENTS.md
cat dcai-unified-kernel/dist/kernel-always-on.md >> your-project/AGENTS.md

# 3. As one prompt file for plain chat UIs
#    paste dist/dcai-single-file.md into the system prompt, or upload it as a knowledge file

# 4. As enforcement
python scripts/dcai.py forecast new --id FC-001 --question "Will X ship before 2026-12-31?" \
  --deadline 2026-12-31 --p 0.6 --base-rate 0.35 --base-source "comparable launches"
python scripts/dcai.py forecast update --id FC-001 --p 0.68 --note "pilot data better than base rate"
python scripts/dcai.py forecast score
```

No install step, no dependencies, Python 3.8+ standard library only. Per-carrier details: [docs/portability.md](docs/portability.md).

## What you get out of it

Feed it a messy high-stakes question and a compliant answer has this shape:

| 关键主张 (claim) | 类型 (type) | 核验状态 (status) | 依据/来源 (source) | 证据强度 (strength) | 反向证据或限制 (counter) | 对结论的影响 (impact) |
|---|---|---|---|---|---|---|
| Unit cost fell 30% in 2025 | evidence | partially supported | supplier filing, p.12 | medium | single supplier, self-reported | supports the margin case |

…followed by mechanism, counter-evidence, unknowns, applicability, and the specific observation that would overturn the conclusion. Not "it depends".

## Hard guarantees

`scripts/dcai.py` refuses the moves that corrupt a forecast record:

| Attempt | Result |
|---|---|
| Let the model choose the probability instead of you | rejected — `p_owner` must be `user`; the model may only supply `--ai-low/--ai-high` |
| Edit the probability after the outcome is known | rejected — resolved cards are closed |
| Resolve the same forecast twice, or retune its resolution criteria | rejected |
| Hand-edit `forecast.json` to make a forecast look better | detected — sealed hash chain plus ledger replay |
| Report a Brier score without a baseline or sample size | blocked by the report — N < 30 is flagged as descriptive only |

```console
$ python scripts/dcai.py forecast resolve --id FC-001 --outcome 1 --source "release log"
FC-001 resolved o=1 | initial Brier=0.1600 | final Brier=0.0900

$ python scripts/dcai.py verify
sealed chain intact: 5 records, hashes contiguous; card state matches ledger replay
```

## Design principles

1. **One source of truth.** `kernel/core.md` and `references/*.md` are authored; `SKILL.md`'s kernel block and everything in `dist/` is generated by `scripts/build.py`. CI fails on drift.
2. **Progressive disclosure by seriousness, not by file order.** A one-off question costs the kernel only; a serious decision pulls one workflow file.
3. **Soft rules where judgement lives, hard rules where arithmetic lives.** No rule that a script can enforce is left to a prompt.
4. **Honest degradation.** Without retrieval, without a workflow file, without a tool, the agent says so instead of performing completeness.
5. **Portable by construction.** Markdown, UTF-8, no framework API, no network, no build toolchain beyond Python's stdlib.

## Layout

```text
SKILL.md                 the skill: kernel (generated) + routing + output contract + index
kernel/core.md           single source of the always-on kernel
references/              19 on-demand workflow files (01-kernel-full … 19-regression)
scripts/build.py         generates SKILL.md kernel block + dist/
scripts/dcai.py          enforcement CLI (forecast / decide / check / verify)
dist/kernel-always-on.md paste-ready kernel for AGENTS.md
dist/dcai-single-file.md kernel + all workflows, for chat UIs
tests/                   46 tests: math, guardrails, tamper detection, structure, docs
docs/                    architecture, portability, usage recipes
```

## Compatibility

| Carrier | Support |
|---|---|
| Claude Code, DSH and other Agent Skills clients | native — drop the directory in the skills folder |
| Codex, Cursor, Aider and other `AGENTS.md` readers | native — append `dist/kernel-always-on.md` |
| ChatBox, ChatGPT, Claude.ai, local UIs | paste `dist/dcai-single-file.md` into the system prompt |
| CI / scripts / cron | `python scripts/dcai.py` |
| MCP servers | wrap the CLI; not shipped yet |

The rule set is language-agnostic; the shipped text is Chinese-first with English metadata and trigger phrases, because the originating corpus was Chinese. English kernel translation is on the [roadmap](CHANGELOG.md).

## Status

`v2.0-alpha` — rules and structure are complete, and the enforcement layer is tested. The **behavioural** claims (does a model actually comply) require regression runs on each specific carrier + model; see [references/19-regression.md](references/19-regression.md) for the T01–T27 suite and the non-compensable failure list. Nothing here claims that a prompt produces technical isolation, automatic memory, or an independent audit.
