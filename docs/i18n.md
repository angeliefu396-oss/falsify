# 双语状态（i18n）

这个项目**中文优先**，因为原始语料是中文。英文不是翻译装饰，是给非中文用户一个能独立工作的入口。

## 现状

| 内容 | 中文 | 英文 |
|---|---|---|
| 常驻内核 `kernel/core.md` | ✅ 完整 | ✅ 完整（`kernel/core.en.md`，手工对齐，非机翻） |
| Skill 入口 `SKILL.md` | ✅ | ✅（`SKILL.en.md`，路由表与索引已译） |
| 安装说明 / README | ✅ | ✅ |
| 详细说明书 | ✅ `MANUAL.md` | ✅ `MANUAL.en.md` |
| 架构 / 可移植性 / 用法 / MCP / 回归 | ✅ | ⏳ 未译（英文手册里给了摘要与指路） |
| 19 个工作流文件 `references/` | ✅ | ⏳ 未译 |

## 英文用户实际会得到什么

- 内核（每轮生效的部分）是**完整英文**，能独立支撑：证据分层、反证、结论强度、预测纪律、权限、自检。
- 路由表是英文，但指向的工作流文件是中文。读到中文文件时，模型仍按英文内核的规则作答——**规则不会因为工作流文件是中文而失效**。
- 单文件载体 `dist/dcai-single-file.md` 是中文内核 + 中文附录，英文用户请用 `dist/kernel-always-on.en.md`。

## 装英文版

```bash
sh install/install.sh --en ~/.claude/skills
```

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install/install.ps1 -Target "$env:USERPROFILE\.claude\skills" -Lang en
```

安装器会把 `SKILL.en.md` 复制成目标目录里的 `SKILL.md`（其余文件原样带上），这样客户端的技能入口仍是标准文件名。

## 参与翻译

1. 只翻 `references/` 里的单个文件，一次一个 PR，便于审。
2. 译名表固定：claim→主张、evidence→证据、verification status→核验状态、user report→用户报告、system inference→系统推断、assumption→假设、unknown→未知、falsifier→推翻条件、evidence strength→证据强度、professional collaboration view→专业协作视图。
3. **不要为了通顺而弱化规则**。"不得""禁止"在英文里用 must not / is prohibited，不要写成 should avoid。
4. 数字与评分公式原样保留，包括 0.25 的说明与 N<30 的护栏。
5. 翻完在文件首行加 `> EN: translated from <commit>` 便于对账。

## 为什么不做机翻全量

机翻会把"不得互换"翻成"should not be confused"，把"禁止回填"翻成"avoid backfilling"——这两句的强度差别，恰好就是这套规则的全部价值。宁可少翻，也不稀释。
