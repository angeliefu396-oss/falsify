## 2. 协议偏差（必须写清楚，否则数字不可信）

1. **评审不是完全盲的**：评审读的是仓库里的回答文件，路径名带着项目名。它能猜到这个回答来自被测试的系统。影响：可能带来轻微宽松。
2. **被测 agent 继承了宿主会话的人格设定**：为避免"角色扮演语气"干扰判定，每个被测 agent 都被要求"中性专业语气、不要角色扮演"。这是一个额外约束，正常用户不会有。
3. **不是一次跑完**：编排器一次只能带 8 个子 agent，所以按 7 条一批分四批跑，再分三批评审。批与批之间是同一模型、同一温度。
4. **T02 的被测 agent 自行追加了"本轮禁止联网"**：用例只限制"不读 references/"，它把"无外部资料"扩大解释了。评审按 criteria 判 PASS，但这属于**自行加限**，记录在案。
5. **T05 的来源无法核验**：回答声称"读取了诺基亚 2026 Q3 中期报告（2026-10-22）"并给出具体数字。评审无法确认这次读取是否真实发生。按 criteria（要列来源、时效）判 PASS，但**这一条存在伪造检索的嫌疑，需人工抽查原文**。它不是"已确认的伪造"，只是"未核实的引用"——两者不能混为一谈。
6. **T11 的判定有争议**：旧轮次没有具体数值预测，回答是"重设命题与兑现标准"而非"修订旧点值"。评审按 PASS 处理；若口径要求"必须显式作废旧预测"，应降为 PARTIAL。

## 4. 两处 PARTIAL 说明了什么

### 4.1 T01：规则写对了，但**触发时机**没写死

`SKILL.md` 原本只写"只回一句"，没说"不许补充什么"。模型读到一份内容丰富的 skill，很容易顺手把内核要点、路由表、索引一起"展示"出来——这在体验上是"加载成功"，在规则上是越界。

处置：已把"首次激活到此为止"写进 `SKILL.md` / `SKILL.en.md`，明确列出禁止补充的六类内容（内核复述、八步、路由表、索引、自检、版本沿革），并指出 T01 会抓这个失败。

### 4.2 T09：八项标准里最容易漏的是"敏感性"

证据分层、选项比较、信息价值、建议强度、执行权限、推翻条件都出现了，唯独敏感性（哪个输入变了结论就翻转、翻转阈值是多少）被"推翻条件"吸收了。这不是格式问题：**没有敏感性，用户不知道自己该盯哪个数。**

处置：不改内核（内核已要求"说明什么信息会改变判断"），但在 T09 的判读里注明"敏感性必须独立成节"，后续版本若重复出现，再考虑把它提升为输出合同的必填栏。

## 5. 这轮结果能说明什么、不能说明什么

**能说明**：这套规则在"解释型任务"上确实生效——27 条里 25 条完整通过，尤其是预测纪律那 9 条（T17–T27 全绿），说明最容易被模型讨好倾向破坏的部分被守住了。

**不能说明**：
- 换一个能力更弱的模型会怎样，未测；
- 换载体（单文件 / AGENTS.md / MCP）会怎样，未测；
- 长对话（>20 轮）后规则是否仍稳，未测；
- 真实高压决策上的实际效果，未测——回归测的是"是否按规则作答"，不是"结论是否正确"。

一句话：**这一轮证明的是"它照做了"，不是"它做对了"。**
