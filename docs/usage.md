# 用法配方

六个高频场景。每段都可以直接粘贴，改掉方括号里的内容即可。

判断"它真的在工作"的标准：**关键主张能被拆成类型 + 来源 + 强度 + 限制，而且能说出什么会推翻结论。** 只给结论和形容词的，就是没工作。

---

## 1. 严肃研究（横纵分析）

> 这是个严肃研究，会用到我的重要决定。
> 研究对象：[某个行业 / 产品 / 制度 / 方法]。
> 先做纵向：起源、阶段划分、关键决策与路径依赖。
> 再做横向：至少 3 个对照对象，按 [成本/性能/生态位/用户分层] 比较。
> 然后横纵交汇：这个对象为什么走到今天这一步。
> 关键主张给类型、来源、强度、反向证据。最后说：什么新信息会推翻你的判断。

**期待**：阶段划分 + 对照表 + 交汇结论 + 反证 + 未知 + 推翻条件。
**常见坑**：模型容易写成编年史。发现只有时间线没有"决策逻辑"时，回一句：把每个阶段的关键决策、当时可选项和为什么没选另一条补上。

---

## 2. 重大决策 + 决策记录

> 我要决定：[A 还是 B]。
> 先用专业协作视图，把我给的信息分成事实、用户报告、推断、假设、偏好和未知。
> 然后做十阶段决策：定义决策、偏见与利益、证据计划、信息价值、证据审计、选项比较、敏感性与反事实、推荐、执行权限、可证伪与确认。
> 不要替我定价值权重；给出结论强度（信息呈现/弱建议/条件建议/较强建议）。
> 最后把这次决策写成决策记录，只把真正影响选择、未来可兑现的关键假设转成预测卡。

CLI 侧配套：

```bash
python scripts/dcai.py decide new --id DEC-001 --question "要不要从 A 转到 B"
python scripts/dcai.py forecast new --id FC-001 --question "6 个月内 B 方向是否拿到第一个付费客户？" \
  --deadline 2027-04-30 --p 0.45 --base-rate 0.3 --base-source "同类转型样本"
```

**期待**：证据表 + 选项比较表（含"维持现状""延迟""可逆试验"）+ 推荐强度 + 执行权限 + 推翻条件。
**常见坑**：只给两个选项。内核要求检查假二选一——发现缺"延迟/小试验/退出"就该追问。

---

## 3. 反方压力测试 / 预演失败

> 我准备做 [X]，已经倾向这么干了。
> 不要帮我论证。你的任务是：给出最强的反对理由，指出我可能忽略的替代解释，做一次预演失败（假设 12 个月后彻底失败，倒推最可能的三个原因），并列出我最可能自欺的三个地方。
> 只保留有具体机制的反驳，不要泛泛风险清单。

**期待**：具体机制 + 替代解释 + 三个失败路径 + 自欺点。
**常见坑**：模型会软化。加一句"我不需要被照顾情绪，需要被证伪"。

---

## 4. 把重复工作做成系统 / SOP / Skill

> 这个任务我每月要做一次，[简述流程]。
> 先判断值不值得做成系统：比较"直接做一次"和"建系统的维护成本"。
> 值得的话按 SBE 走：唯一使命与可观察结果 → 任务原子 → 系统合同 → 代表性样例 → 要求追踪 → 回归测试 → 发布维护。
> 保留反复杂度门：如果维护成本高于收益，明确建议降级成模板。

**期待**：必要性判断先行 + 合同（输入/输出/边界/失败处理）+ 样例清单 + 测试方法。
**常见坑**：一次性任务被做成大系统。内核要求先算维护账。

---

## 5. 预测登记与复盘（含 CLI）

规则三句话：**概率归你，只追加不覆盖，评分必须带基线。**

```bash
# 建卡：p 是你自己确认的概率；模型只能给范围
python scripts/dcai.py forecast new --id FC-001 \
  --question "该功能是否在 2026-12-31 前达到 1 万日活？" \
  --deadline 2026-12-31 --p 0.6 --ai-low 0.55 --ai-high 0.72 \
  --base-rate 0.35 --base-source "同类功能 12 个月达标记录"

# 新证据来了：追加，不覆盖
python scripts/dcai.py forecast update --id FC-001 --p 0.68 --note "灰度留存高于基线 4pp"

# 到期兑现一次，落封印
python scripts/dcai.py forecast resolve --id FC-001 --outcome 1 --source "后台统计 2026-12-31"

# 出报告（初始/最终 Brier、更新增益、同题集基线、分档校准、小样本警告）
python scripts/dcai.py forecast score

# 每季度查一次有没有人手工改账
python scripts/dcai.py verify
```

**复盘要分开两栏**：过程质量（问题定义、证据分层、基础率、反证、更新及时性）与现实结果（成/败、执行偏差、随机性）。好结果可能来自坏过程。

---

## 6. 审计一个已经形成的判断

> 我现在的判断是：[一句话]。
> 不要重新论证它。请审计：这个判断依赖哪些隐含假设？每条假设的核验状态是什么？哪一条一旦不成立，结论就倒？我当初可能忽略了什么反向证据？

**期待**：假设台账 + 每条的可证伪方式 + 最脆弱的支撑。
**常见坑**：模型会复述你的判断以示理解。要求它"只列假设和反证，不复述结论"。

## 提示词里可以用的短语

| 说这句 | 触发什么 |
|---|---|
| 用专业协作视图，不要讲故事 | 证据分层表 + 综合判断 |
| 只用我给的资料，把事实/推断/未知分开 | 封闭资料模式，禁止静默补外部知识 |
| 帮我压测这个判断 | 超级合伙人审计（`05-partner-audit.md`） |
| 做完整横纵研究，并列反向证据 | 研究工作流（`07-research.md`） |
| 方向定了，做路径与杠杆优化 | 执行工作流（`09-execution.md`） |
| 把这次决定登记成决策记录和预测卡 | 预测校准（`11-forecast.md`）+ CLI |
| 显示路由、假设和自检 | 工程审计视图 |
| 登记这次错误，先别改内核 | 错误处理流程，避免单例补丁 |
