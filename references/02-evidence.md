# [EVIDENCE] 二、循证分层、证据质量与假设协议

## 1. 主张类型

严肃研究、决策和系统设计中的关键主张必须使用以下类型。可以使用中文全称，不要求用户记代码。

| 类型              | 定义                | 能否直接当成外部事实   |
| --------------- | ----------------- | ------------ |
| 已核验事实 FACT      | 经适当来源直接确认且仍在有效期内  | 可以，但注明范围和时间  |
| 证据 EVIDENCE     | 支持或反对某个主张的材料      | 不能；需解释支持力度   |
| 用户报告 REPORT     | 用户对经历、数据或观察的陈述    | 不能；除非另行核验    |
| 用户偏好 PREFERENCE | 用户的价值排序、容忍度和取舍    | 不能，但应进入决策    |
| 系统推断 INFERENCE  | 根据现有证据形成的解释或结论    | 不能；须给出推理依据   |
| 假设 ASSUMPTION   | 分析暂时依赖但尚未充分验证的命题  | 不能；须有验证或推翻条件 |
| 决定 DECISION     | 用户已作出的选择或经授权形成的决定 | 是决策状态，不是世界事实 |
| 未知 UNKNOWN      | 当前资料不足、冲突或不可观察    | 不能；不得静默补齐    |

## 2. 核验状态

类型与核验状态必须分开：

- 未核验；
- 部分支持；
- 较强支持；
- 已核验；
- 有争议；
- 已证伪；
- 已过期；
- 不可直接核验。

示例：“用户报告 + 未核验”与“系统推断 + 较强支持”都是合法组合；“资料里写了”只证明资料存在该说法。

## 3. 证据强度

证据强度只针对“证据对当前主张的支持力”，不等于来源名气。使用：

- **强**：直接、方法可靠、时效与适用性良好，且有独立支持或可复核；
- **中**：方向有支持，但直接性、方法、样本、时效、独立性或适用性至少一项有限；
- **弱**：个案、专家意见、相关性、间接材料、模型记忆或未经充分核验的叙述；
- **不可用**：与主张无关、过期到会改变结论、来源无法辨认、明显伪造或受到未处理的严重污染。

判断时至少检查：相关性、直接性、方法可靠性、时效性、独立性、用户适用性、利益冲突和可复核性。不能仅以“官方/论文/专家/亲身经历”一词自动定级。

## 4. 来源模式

- **封闭资料**：只使用用户指定资料；缺失就写缺失。
- **资料优先**：资料为主，外部知识必须单列并标明是否核验。
- **开放研究**：允许检索外部来源，标注事件日期、发布日期、链接和检索日期。
- **混合分区**：不同任务原子采用不同模式，必须明确分区，不能静默切换。

当前事实优先使用原始数据、官方规则、论文或直接文档；技术问题优先官方文档和原始论文。多个转载自同一源不能算多个独立证据。

## 5. 关键假设台账

只记录错误后会改变结论、计划或风险的假设：

```markdown
| 假设 | 提出者 | 当前支持 | 反向证据 | 依赖它的结论 | 状态 | 验证方式 | 推翻条件 | 失效影响 |
|---|---|---|---|---|---|---|---|---|
```

假设状态：待验证、暂时支持、被质疑、已证伪、已过期、知情接受、已升级为事实。

关键假设失效时，必须更新所有依赖它的下游结论、决定、计划和预测，不能只在台账中改一行。

## 6. 证据可见性规则

- 简单低影响问题可以直接回答，不机械展示表格。
- 标准或深度的研究、选择、职业/财务/医疗等高影响任务，关键主张必须让用户看见类型、依据、强度和未知。
- “自然语言表达”只能改变句式，不能隐藏事实与推断的边界。
- 证据表之后必须有综合判断，不能只罗列材料而拒绝权衡。
